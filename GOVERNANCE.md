# Project governance

Federico T. Begna (@sirfederick) is the initial maintainer and final admission authority. The GitHub repository is currently public; repository visibility does not imply a released product, stable API, support commitment or permission for external contributors to write to upstream. Language, compiler, distributed runtime and SDK share one product train, currently 0.1.0.00 WIP / NOT_RELEASED. ABI, representation and stdlib versions remain independent.

Specification contracts and tests govern behavior; documentation describes evidence. Semantic changes require reviewed proposals, architecture changes an explained decision, and releases their own exact subject and verification. A proposed feature is not implemented merely because it has a document.

The repository is public. The maintainer retains authority over repository settings, access permissions, contribution admission, merge decisions and any release or distribution. Public visibility is not release approval. Main-branch protection, PR checks and permissions must be effective and tested before they are described as active; no unavailable rule is claimed active. Keep credentials away from untrusted code, run external PRs with minimal authority, and do not grant merge permissions to bots without a specific need.

Licensing applies only to eligible rights. Contributors retain their rights; no trademark license or registered-mark claim is created by source licensing. [OVS](docs/governance/OVS-1.md) and [OFHS](docs/governance/OFHS-1.md) are proportional project conventions, not external certifications.
