# Project governance

Federico T. Begna (@sirfederick) is the initial maintainer and final admission authority. Language, compiler, distributed runtime and SDK share one product train, initially 0.1.0.00 WIP / NOT_RELEASED. ABI, representation and stdlib versions remain independent. There is no release, public repository or stability guarantee implied by this preparation.

Specification contracts and tests govern behavior; documentation describes evidence. Semantic changes require reviewed proposals, architecture changes an explained decision, and releases their own exact subject and verification. A proposed feature is not implemented merely because it has a document.

Before publication, the maintainer separately authorizes repository visibility and the integrated release. Future main protection, PR checks and permissions must be effective and tested; no unavailable rule is claimed active. Keep credentials away from untrusted code, run external PRs with minimal authority, and do not grant merge permissions to bots without a specific need.

Licensing applies only to eligible rights. Contributors retain their rights; no trademark license or registered-mark claim is created by source licensing. [OVS](docs/governance/OVS-1.md) and [OFHS](docs/governance/OFHS-1.md) are proportional project conventions, not external certifications.
